# MOCHIPOYO Alert Research ファイル整理・番号付け契約

## 1. ユーザーの意図

番号は説明文に付けるものではない。

ユーザーがエクスプローラー上で似た名前のファイルを探さなくて済むように、**実際のファイル名そのもの**へ `01_`、`02_`、`03_` の連番を付ける。

実行ファイルだけでなく、ユーザーが確認・提出する出力ファイルも同じ方針で整理する。

## 2. 適用範囲

この契約は、2026-07-22以降に新しく作成するStage・実行ファイル・ユーザー向け出力へ適用する。

現在稼働中のM7C既存ファイルは変更しない。既存M7CのBAT・ログ・CSV・JSONを番号付け目的だけでrename、移動、再生成しない。

## 3. 新しい実行ファイル

同じStageでユーザーが直接操作する実行ファイルは、専用フォルダへまとめ、実ファイル名を実行順に番号付けする。

例:

```text
scripts/mochipoyo_alert_research/m8a/operator/
  00_READ_ME_FIRST.txt
  01_run_prepare_m8a_inputs.bat
  02_run_m8a_coverage_audit.bat
  03_open_m8a_results.bat
  04_stop_m8a_monitor.bat
```

ルール:

- 番号は物理ファイル名の一部
- 説明だけに番号を付けて済ませない
- 同じ役割の似た名前を同一フォルダへ散在させない
- 実行順にエクスプローラーで上から並ぶようにする
- ユーザーが直接使わない内部Pythonモジュールまで無理に番号化しない
- 起動用、停止用、確認用を同じoperatorフォルダへまとめる

## 4. 新しい出力ファイル

同じ実行で作られたユーザー向け出力は、Stage名とrun IDまたは日時で分けた1フォルダへまとめ、実ファイル名を番号付けする。

例:

```text
outputs/mochipoyo_alert_research/M8A/20260722_180000/
  00_READ_ME_FIRST.txt
  01_summary.json
  02_status.json
  03_source_matched.csv
  04_missed_source.csv
  05_extra_candidates.csv
  06_audit.log
```

ルール:

- ユーザーが確認・提出するファイルは実ファイル名へ番号を付ける
- 通常提出に必要なものをcollector、m7c、derivedなど複数フォルダから探させない
- 同じ実行の成果物は1つのrunフォルダへ集約する
- `00_READ_ME_FIRST.txt`に、各ファイルの意味、提出対象、実行時刻、Stage、commitを記載する
- 既存の内部ログを維持する必要がある場合でも、提出用runフォルダへ必要ファイルをコピーまたは生成してまとめる
- ファイル名だけで内容が分かるよう、番号の後ろに短く明確な役割名を付ける

## 5. 提出用パッケージ

新しいStageでは、ユーザーに複数フォルダを探させない。

通常確認・正式レビュー時には、次のどちらかを作る。

```text
99_UPLOAD_PACKAGE/
```

または

```text
99_UPLOAD_PACKAGE.zip
```

中には、その時点で提出が必要な番号付きファイルだけを入れる。

## 6. 引き継ぎ文の必須記載

今後の引き継ぎ文には次を明記する。

- 既存ファイルを変更するのか、次Stageから適用するのか
- 実在する番号付き実行ファイルの正確な名前
- 実行ファイルが入っている1つのフォルダ
- 実行順
- 出力がまとまる1つのrunフォルダ
- 提出用フォルダまたはZIPの正確な場所
- 提出タイミング

禁止:

- 説明上だけ `01`、`02` と番号を付ける
- 実在しない将来名を、現在実行できる名前として案内する
- ユーザーに似た名前のファイルを複数フォルダから探させる
- 必要ファイルを後から小分けに追加要求する

## 7. 現在のM7Cへの扱い

現在のM7Cは有効なprospective collection中であるため、番号付けのためだけに停止・rename・再初期化しない。

この契約は、M7C正式レビュー後に新しく作るM8A以降の実行・出力構成から適用する。
