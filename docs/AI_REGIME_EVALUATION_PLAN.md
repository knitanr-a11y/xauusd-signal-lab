# AI相場環境評価プラン

このドキュメントは、バックテストで悪かった期間を単純に削るのではなく、
その期間の相場状態を記録し、将来のリアルタイム通知時にAIへ読ませて評価材料にするための設計メモです。

## なぜ単純に削らないのか

特定の月や特定の負け方に合わせて条件を削ると、その期間には最適化できても、
他の期間で利益になっていたトレードまで消す可能性がある。

特に、現在の `xm_kiwami_gold_abc_v3` は長期でプラスが出ているため、
一部の弱い月だけを理由にA/B/C/C2の条件を大きく変えるのは危険。

## 基本方針

- ルール本体はまず壊さない。
- 悪かった期間を「負けパターン事例」として保存する。
- 将来シグナルが出たとき、現在の相場が過去の悪い相場に似ていないかをAIに判定させる。
- AIは最終判断をせず、裁量確認の注意点を出す。
- 最終判断は人間が行う。

## 2025年3月の位置づけ

`xm_kiwami_gold_abc_v3` の2025年3月は、長期成績の中では弱い月だった。

概要:

```text
14回
5勝9敗
-1.5R
PF 0.833
DD 6.0R
```

モデル別:

```text
A: 4回 / 1勝3敗 / -1.5R
B: 2回 / 0勝2敗 / -2.0R
C: 8回 / 4勝4敗 / +2.0R
```

重要:

- 2025年3月は、Cだけが悪いわけではない。
- AとBがマイナスで、Cは月間ではプラス。
- 単純にCを削ると、後半で取り返した勝ちも消える可能性がある。
- そのため、2025年3月は「条件削除」よりも「AIに読ませる負け相場サンプル」として扱う。

## AIに読ませたい情報

将来シグナルが出たとき、AIには以下を渡す。

### 1. 現在のシグナル情報

- ブローカー
- 口座種別
- シンボル
- 時間足
- モデル種別 A / B / C / C2
- BUY / SELL
- シグナル時刻
- JST時刻
- エントリー候補価格
- SL
- TP
- リスクリワード
- risk / ATR
- ATR
- スプレッド

### 2. 上位足の状態

- H1方向
- H1 EMA20 / EMA50 / EMA200 の位置関係
- H1 EMA乖離
- H1の直近高値安値
- H1がトレンドかレンジか
- H1のボラティリティ拡大/縮小

### 3. M15の状態

- M15 EMA20 / EMA50 / EMA200 の位置関係
- MACDライン
- MACDシグナル
- MACDヒストグラム
- MACDヒストグラム加速/減速
- 直近スイング高値安値
- ブレイク直後か、押し戻されているか
- 直近数本のローソク足の実体/ヒゲ

### 4. 過去の似た負けパターン

例: 2025年3月の負け相場

- 月初〜中旬に負けが集中
- 上に抜けたように見えてC BUYが押し戻される
- A/Bも少数ながら損失
- BUY/SELLどちらか一方だけではなく、方向感が不安定
- 複数日でSLが続いた

## AIに聞くこと

リアルタイム通知時のAI評価では、以下を聞く。

```text
このシグナルは、過去に負けが集中した2025年3月のような相場状態に似ていますか？
似ている場合、どの点が似ていますか？
違う場合、どの点が違いますか？
エントリーを見送るべき注意点はありますか？
SLが浅すぎる、または押し戻されやすい形になっていませんか？
上位足と下位足の方向が噛み合っていますか？
```

## AI出力の理想形

AIには、以下のような出力をさせる。

```text
判定: 通常 / 注意 / 強い注意 / 見送り候補

理由:
- H1は上向きだが、M15では直近ブレイク後に押し戻しが強い
- MACDヒストグラムの伸びが弱く、2025年3月のC BUY負けパターンに似ている
- risk/ATRが大きく、SL到達までの余裕が少ない

確認ポイント:
- 次のM15足で高値を維持できるか
- EMA20上で終値を維持できるか
- 直近安値を割らないか
```

## やってはいけないこと

- AIに最終エントリー判断を丸投げしない。
- AIの評価だけで売買しない。
- 一つの悪い月だけを理由にルールを削りすぎない。
- 成績が良い期間を無視して、悪い期間だけに最適化しない。
- バックテスト条件とリアルタイム評価条件を混同しない。

## 実装ステップ

### Phase 1: 負け相場ケースの保存

- 2025年3月の負けトレードをCSVとして保存する。
- その月の要約をMarkdown化する。
- A/B/C/C2別、BUY/SELL別、時間帯別に特徴を残す。

### Phase 2: シグナルごとの説明データ作成

- シグナル発生時に、AIへ渡すJSONまたはMarkdownを作る。
- 価格、ATR、MACD、EMA、H1状態、直近ローソク足を含める。

### Phase 3: AI評価プロンプト作成

- 過去の悪いケースと現在シグナルを比較させる。
- 出力は「通常 / 注意 / 強い注意 / 見送り候補」に統一する。

### Phase 4: Discord通知に追加

- Discord通知にAI評価を追記する。
- ただし、AI評価は補助情報として扱う。
